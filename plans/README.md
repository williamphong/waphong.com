## Findings considered and rejected

- `w-screen` sticky section headers causing horizontal overflow with a
  classic scrollbar: measured on a production build at 390/640/800/900/1023/1024 px
  with a forced 15 px scrollbar — `scrollWidth == clientWidth` everywhere. Not
  a bug.
- Spotlight canvas allocated on touch devices: one ~1.3 MB backing store and
  a compositing layer, no CPU (the rAF loop parks itself). Not worth a change.
- Scroll-spy test passing on a transient state: the assertions are
  auto-retrying and the final state matches the asserted one; no false pass
  found. Not worth changing.
- `useImperativeHandle` without deps in `icons.tsx`, spotlight listener
  cleanup, `useSyncExternalStore` mounted flags, `max-w-screen-xl` in
  Tailwind v4: all verified correct.
- Extracting a shared root layout from the three route groups: separate root
  layouts are a documented decision (`README.md`). Not a finding.
- Pre-commit hooks, `.editorconfig`, `.nvmrc`: CI already gates lint/format
  on every PR and `packageManager` pins pnpm; a third formatting source of
  truth adds noise. Not worth doing.
- CSP `'unsafe-inline'`, HSTS without preload, `images.unoptimized`,
  Renovate's 7-day release age, `import/no-unresolved` off: all documented,
  deliberate decisions in code comments.
- `pnpm audit --audit-level moderate`: no known vulnerabilities (2026-09-07).
  No credentials in the repo; `.dev.vars` is gitignored and holds one
  non-secret key name.

## Unplanned findings (ask for a plan if wanted)

Ordered roughly by leverage. Each is real and vetted; none is planned
because it is either the owner's design call, lower value than the nine
above, or a refactor that would collide with them.

1. **`motion` costs ~33-40 KB gzipped of the ~195 KB first-load JS on every
   route** — for five social-icon hover animations and the theme-toggle
   icon (`components/pqoqubbw/icons.tsx`, 1,130 lines, of which `SpotifyIcon`
   and `ArrowRightIcon` are never imported). `optimizePackageImports` and
   `LazyMotion`/`domAnimation` are already in place, so the remaining lever
   is replacing the animations with CSS or accepting the cost. Owner's call.
2. **CI builds Next twice and re-downloads Chromium every run** —
   `opennextjs-cloudflare build` (runs `next build`) then Playwright's
   `webServer` runs `pnpm build` again; `playwright install` has no cache.
   ~25-30% of a ~110 s run. Fix: `command: process.env.CI ? 'pnpm start --port 3100' : 'pnpm build && pnpm start --port 3100'`
   in `playwright.config.ts` plus `actions/cache` for `~/.cache/ms-playwright`.
   Also add a `typecheck` script (`tsc --noEmit`, 0.7 s warm) as a fast CI
   step before the build.
3. **CI never exercises the Worker artifact.** The one production incident
   this repo documents (every blog post 404ing through the Worker,
   `README.md` / `open-next.config.ts`) is not reproducible by `pnpm test`,
   which runs `next start`. A 4-route smoke test against
   `opennextjs-cloudflare preview` would have caught it. Effort M.
4. **Duplication in the portfolio components** — the card wrapper and hover
   background are copied verbatim in `ExperienceList.tsx`, `ProjectList.tsx`
   and `EducationList.tsx` (and have already drifted in class order); the
   tag pill is duplicated; the sticky section header block appears four times
   in `page.tsx`; the socials array is duplicated between `Footers.tsx` and
   the gallery's `Socials.tsx`; the skip link and `ThemeProvider` props are
   triplicated across the root layouts. Extract `ListCard`, `TagPill`,
   `SectionHeader`, `SkipLink`, and a `lib/socials.ts`. Do this after 004/006/007.
5. **Dead code and config**: `education[].classes` and `projectsData[].date`
   are never rendered; `SpotifyIcon`/`ArrowRightIcon` unused; empty
   `@layer base {}` / `@layer components {}` and the empty `fonts.css` import
   in `globals.css`; `variable: '--font-ibm'` never used; CSP `img-src` and
   `images.remotePatterns` allow `i.scdn.co` and `lh3.googleusercontent.com`
   though nothing references them; `components.json` declares `lucide` with
   no dependency; `components/ui/button.tsx` has five variants whose tokens
   (`bg-primary`, `border-input`, `bg-accent`, …) are defined nowhere, so
   only the hand-overridden `outline` use in the theme toggle works — and it
   carries four runtime deps (`@radix-ui/react-slot`, `class-variance-authority`,
   `clsx`, `tailwind-merge`, the last ~8 KB gz) for that one button.
   Also `poweredByHeader: false` (the live site sends `x-powered-by`) and
   `persist-credentials: false` on `actions/checkout`.
6. **IBM Plex Mono is preloaded on every page** (10 KB) although only the
   blog uses it — Turbopack hoists the blog layout's `@font-face` into the
   shared CSS chunk. MED confidence on the fix (import order); needs a rebuild
   to verify.
7. **`pnpm-workspace.yaml` overrides are mostly stale**: `fast-xml-parser`
   and `js-yaml` are not installed at all; most `<version` overrides target
   versions already superseded. Remove one at a time, confirming resolved
   versions do not move. Renovate's weekly lockfile maintenance exists so
   this block stops accreting.
8. **Renovate keeps reopening a TypeScript 7 PR** that fails because
   `typescript-eslint@8` does not support TS 7; pin `typescript <7` in
   `renovate.jsonc` with a comment naming the blocker.
9. **README drift**: "New features are developed on my test branch" (no such
   branch), transfonter credit for font subsetting (no self-hosted fonts),
   no mention of `pnpm test` or `playwright install`.
10. **`.vscode/settings.json`** enables format-on-save without naming Prettier
    as `editor.defaultFormatter`, and `prettier.resolveGlobalModules: true`
    lets a global Prettier of another major run. **`eslint.config.mjs`** sets
    `@typescript-eslint/no-unused-vars` to `off` with an options object that
    is therefore ignored, so the intended `^_` ignore pattern has no effect.
11. **Direction — the blog**: three placeholder posts from Nov 2025 with
    generic bodies, linked prominently ("Visit my blog") and in the sitemap.
    Publish one real post (PromptCARLA or iCHARM), unlink until content

## Execution notes (2026-09-07)

All nine executed in one pass on `update-portfolio-content`. Deviations and
findings that were not in the plans:

- **003**: the video re-encode came in at 98 KB at the planned `-crf 38`,
  far under the 500 KB budget, so it was re-run at `-crf 30` (184 KB) to
  spend the headroom on quality. `public/images/projects` 3,012 KB → 388 KB.
- **006**: implemented as darkened `-deep` tokens per the owner decision.
  Three neutral steps cannot all clear AA on a light ground, so `muted` as
  *text* was folded into `subtle-deep`; the stock tokens remain for
  backgrounds, borders and the dark theme.
- **006/008, new finding**: the gallery card subtitle used raw
  `text-neutral-500` on a `bg-neutral-100` card — 4.35:1, an AA failure the
  audit had not catalogued (it only listed `rpd-*` tokens). Moved onto the
  palette. The comment at `GalleryCards.tsx:21` records an earlier hand-fix
  to the *title* on the same card; the subtitle was missed then.
- **008, test-design finding**: `.animate-page-fade` runs a 0.4 s opacity
  fade on every route, and axe composites ancestor opacity into its contrast
  maths — so a scan started on `load` reads every text node at ~10 % alpha
  and reports the whole page as failing in *both* themes. `axe.spec.ts`
  waits for `document.getAnimations()` to settle first. Any future spec that
  measures colour must do the same.
- **009**: `date: 'Present'` on PromptCARLA was set to `'Sep 2025 - Present'`
  to match the format of every other live entry. **The start month is
  inferred, not sourced** — correct it if wrong. The field is not rendered.

Measured after (production build, `networkidle`): `/` 314 KB (was ~1.93 MB),
`/projects` 310 KB, `/gallery` 295 KB. `pnpm test` 65 passed. Branded 404
verified against the OpenNext Worker preview, not just `next start`.
